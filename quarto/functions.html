Check columns

Stops with a message naming the missing columns, and never any values, if a workbook lacks a column the code needs. Used by 1. Import data.

# Stop if a data frame lacks any expected column. The message names the
# missing columns only, never values.
check_columns <- function(data, expected, source_name) {
  missing_columns <- setdiff(expected, names(data))
  if (length(missing_columns) > 0) {
    stop(str_glue(
      "{source_name} lacks expected columns: ",
      "{str_c(missing_columns, collapse = ', ')}"
    ))
  }
  invisible(data)
}

Check for repeated patients

Stops if a patient number appears more than once in an input that should have one row per patient. Stata’s merge 1:1 and reshape …, i(PatientNumber) made this check as a side effect; full_join() checks only the rows it matches and pivot_longer() checks nothing, so the import calls this on each sheet. The message gives only the number of repeated patients.

Click to show/hide R Code 
# Stop if a patient number appears more than once in a one-row-per-patient
# input. Stata's "merge 1:1" and "reshape ..., i(PatientNumber)" stopped on
# duplicates; full_join() and pivot_longer() do not check every row, and a
# duplicated row would change a patient's stratum and the four-row era
# rule. The message gives the number of duplicated patients, never which.
check_unique_patients <- function(data, id_column, source_name) {
  n_duplicated <- data |>
    count(.data[[id_column]]) |>
    filter(n > 1) |>
    nrow()
  if (n_duplicated > 0) {
    stop(str_glue(
      "{source_name}: {n_duplicated} patient number(s) appear more than once."
    ))
  }
  invisible(data)
}

Number categories as Stata’s encode did

Stata’s encode turns text into numbered categories in alphabetical order, treating empty text as missing; the first becomes the base level in models. To fit the same models with the same reference categories, R needs factors whose levels are in the same order. sort(method = "radix") sorts in byte order, as Stata does, regardless of the computer’s language settings; R’s ordinary sort can place capitals and accented letters differently. The codes are then as.integer() of the factor.

Click to show/hide R Code 
# Stata's encode turns a text variable into numbered categories, numbering
# the distinct values in alphabetical (byte) order, with empty text as
# missing. This returns a factor with its levels in that order, so the
# reference level and the codes match the original code. The codes are
# as.integer() of the factor.
encode_like_stata <- function(x) {
  x <- na_if(x, "")
  value_order <- sort(unique(x[!is.na(x)]), method = "radix")
  factor(x, levels = value_order)
}

Clean a cohort

What both workbook sheets need before they can be reshaped: drop the unused _Place columns; give the outcome columns names ending in _0 (before the visit) and _1 (after it), as the original code renamed them for Stata’s reshape; number race, sex and age group as encode did, keeping race’s numeric code for the race groups; and make the year of the visit a category, as Stata’s i.IndexTestYear treats it, with 2009 as the reference. The year is renamed only where present, because the control sheet need not have it.

Click to show/hide R Code 
# The cleaning both cohorts share: drop the unused place columns, number the
# text categories as Stata's encode did, keep each race value's code for
# the race groups (R/02_build_long_data.R), and give the outcome columns
# names ending in _0 (before the visit) and _1 (after it), as the original
# code's renames did before reshaping.
clean_cohort <- function(cohort_raw, place_columns) {
  cohort_raw |>
    select(-all_of(place_columns)) |>
    rename(
      patient_number = PatientNumber,
      engaged_in_care_0 = EngageInCare_Before,
      engaged_in_care_1 = EngagedInCare_After,
      retained_in_care_0 = RetainedInCare_Before,
      retained_in_care_1 = RetainedInCare_After,
      vl_0 = VL_Before,
      vl_1 = VL_After
    ) |>
    # The original code never reads the year in the control sheet, so it
    # is renamed only where present
    rename(any_of(c(index_test_year = "IndexTestYear"))) |>
    mutate(
      race = encode_like_stata(Race),
      race_code = as.integer(race),
      gender = encode_like_stata(Gender),
      age_group = encode_like_stata(AgeGroup),
      # Stata's i.IndexTestYear treats each year as a category, with the
      # earliest as the reference
      across(any_of("index_test_year"), factor)
    ) |>
    select(-Race, -Gender, -AgeGroup)
}

Group race codes

Turns race codes into the four race groups from a list of codes per group (the lists are in Setup). A loop over the groups is clearer here than a long case_when(), and a code in no group stays missing, as in the original code.

Click to show/hide R Code 
# Group race codes into the four race and ethnicity groups, from a named
# list of codes per group (R/setup.R). Codes in no group are missing.
group_race_codes <- function(race_code, codes_by_group) {
  group <- rep(NA_character_, length(race_code))
  for (group_name in names(codes_by_group)) {
    group[race_code %in% codes_by_group[[group_name]]] <- group_name
  }
  factor(group, levels = names(codes_by_group))
}

Reshape to one row per period

From one row per patient, with each outcome in a _0 and a _1 column, to two rows per patient, with post_visit 0 for the period before the visit and 1 for after. names_pattern splits each column name into the outcome and the period; .value makes the outcome part a column name. This is Stata’s reshape long …, i(PatientNumber) j(Intervention).

Click to show/hide R Code 
# One row per patient and period: post_visit is 0 for the period before the
# index visit and 1 for the period after it, as Stata's
# "reshape long ..., j(Intervention)" did with the 0 and 1 suffixes.
reshape_to_long <- function(cohort_wide) {
  cohort_wide |>
    pivot_longer(
      cols = c(
        engaged_in_care_0, engaged_in_care_1,
        retained_in_care_0, retained_in_care_1,
        vl_0, vl_1
      ),
      names_to = c(".value", "post_visit"),
      names_pattern = "(.*)_([01])"
    ) |>
    mutate(post_visit = as.integer(post_visit))
}

Viral load outcomes

Two binary versions of the viral load result (analysis plan §7): vl_suppressed is missing when the result is, and vl_suppressed_missing_fail counts a missing result as not suppressed. coalesce() replaces the missing values with 0, as the original code’s replace … if … == . did.

Click to show/hide R Code 
# Two binary viral load outcomes (analysis-plan.md 7.3): vl_suppressed keeps
# a missing result missing; vl_suppressed_missing_fail counts it as not
# suppressed. A value other than the two recorded results is also missing,
# as in the original code.
add_viral_load_outcomes <- function(cohort_long, suppressed, not_suppressed) {
  cohort_long |>
    mutate(
      vl_suppressed = case_when(
        vl == suppressed ~ 1L,
        vl == not_suppressed ~ 0L,
        .default = NA_integer_
      ),
      vl_suppressed_missing_fail = coalesce(vl_suppressed, 0L)
    )
}

McNemar’s test

The paired test of Methodological background. It returns the four kinds of pair, the proportions before and after, the uncorrected chi-squared statistic and its P value, and the exact P value from a binomial test on the discordant pairs, which is what Stata’s mcc reports. Writing the statistic out makes it visible that only the discordant pairs matter. With no discordant pairs, or no complete pairs, there is no test; the function returns missing statistics with n_discordant and n_pairs, which say which case it is, instead of stopping the whole pipeline.

Click to show/hide R Code 
# McNemar's test for one binary outcome measured before and after the visit
# on the same patients, as Stata's mcc reports it: the four paired counts,
# the uncorrected chi-squared test, and the exact test (a binomial test on
# the discordant pairs). Patients missing either value are left out. With
# no complete pairs, or no discordant pairs, there is no test: the
# statistics are missing and n_pairs and n_discordant say why, so the
# pipeline carries on to the other outcomes.
paired_mcnemar <- function(cohort_wide, before, after) {
  pairs <- cohort_wide |>
    filter(!is.na(.data[[before]]), !is.na(.data[[after]]))
  counts <- pairs |>
    count(before = .data[[before]], after = .data[[after]])
  n_after_only <- sum(pairs[[before]] == 0 & pairs[[after]] == 1)
  n_before_only <- sum(pairs[[before]] == 1 & pairs[[after]] == 0)
  n_discordant <- n_after_only + n_before_only
  chi_squared <- NA_real_
  p_value <- NA_real_
  p_value_exact <- NA_real_
  odds_ratio <- NA_real_
  conf_low <- NA_real_
  conf_high <- NA_real_
  if (n_discordant > 0) {
    chi_squared <- (n_after_only - n_before_only)^2 / n_discordant
    p_value <- pchisq(chi_squared, df = 1, lower.tail = FALSE)
    exact <- binom.test(n_after_only, n_discordant)
    p_value_exact <- exact$p.value
    # The matched-pairs odds ratio, after-only over before-only pairs, with
    # the exact interval mcc reports: the binomial interval for the share of
    # discordant pairs that improved, p, turned into odds p / (1 - p). It is
    # infinite when no pair got worse, as the article's Table 4 footnotes.
    odds_ratio <- n_after_only / n_before_only
    conf_low <- exact$conf.int[1] / (1 - exact$conf.int[1])
    conf_high <- exact$conf.int[2] / (1 - exact$conf.int[2])
  }
  list(
    counts = counts,
    n_pairs = nrow(pairs),
    n_discordant = n_discordant,
    proportion_before = if (nrow(pairs) > 0) mean(pairs[[before]]) else NA_real_,
    proportion_after = if (nrow(pairs) > 0) mean(pairs[[after]]) else NA_real_,
    n_before = sum(pairs[[before]]),
    n_after = sum(pairs[[after]]),
    odds_ratio = odds_ratio,
    conf_low = conf_low,
    conf_high = conf_high,
    chi_squared = chi_squared,
    p_value = p_value,
    p_value_exact = p_value_exact
  )
}

Crosstabs with row percentages

For one characteristic and one outcome, the number of patients in each combination, with missing values kept, and the percentage within each category of the characteristic: Stata’s tab predictor outcome, row missing. The percentages are of all patients in the category, missing outcomes included, so for viral suppression with missing excluded they differ from the proportion among those tested.

Click to show/hide R Code 
# Counts and row percentages of an outcome within each level of a
# characteristic, keeping missing values, as Stata's
# "tab predictor outcome, row missing" shows them
crosstab_row_percent <- function(cohort_long, predictor, outcome) {
  cohort_long |>
    count(.data[[predictor]], .data[[outcome]]) |>
    group_by(.data[[predictor]]) |>
    mutate(row_percent = 100 * n / sum(n)) |>
    ungroup()
}

Conditional logistic regression

The model behind most results (Methodological background). strata(patient_number) makes each patient a stratum, the R version of Stata’s group(PatientNumber), and method = "exact" asks for the exact conditional likelihood, which is what Stata’s clogit computes. The terms are passed as text so the scripts can build many models in loops.

In the RUSH-era models the terms leave out the main effect of a characteristic that is the same in a patient’s two records. Stata drops such a term automatically, with a note; R’s clogit() would return its coefficient as NA. Leaving it out gives the same model and the same coefficients. The era models keep it, because there a characteristic can change between a patient’s two visits (5. Comparison with the pre-RUSH era).

The estimation sample is built as Stata’s clogit builds it: rows that have every variable the model uses, then only patients whose outcome differs between their rows. A patient with the same outcome in every row, or with one row (a viral load in one window only), adds nothing to the conditional likelihood; Stata drops them with a note about “all positive or all negative outcomes”. Categories left with no such patients are then dropped too, so the reference category is the first one that carries information. Without that step, if the first category had only uninformative patients, clogit() would silently drop another category’s interaction instead and the effects would be labelled with the wrong categories. The categories that had patients before the step are kept with the model, so the next functions can report the dropped ones as not estimable rather than leave them out.

Click to show/hide R Code 
# Conditional logistic regression with one stratum per patient, the R
# equivalent of Stata's "clogit outcome ..., group(PatientNumber)". The
# right-hand side lists only terms that vary within a patient: a
# characteristic that is the same before and after the visit cannot have a
# main effect within a patient, so Stata drops it; the RUSH-era models do
# not write it (a term written anyway comes back as NA). method = "exact"
# uses the exact conditional likelihood, as Stata does.
# The estimation sample is built as Stata's clogit builds it: rows with
# every variable the model uses, then only patients whose outcome differs
# between their rows, because a patient whose outcome is the same in every
# row (or who has one row) adds nothing to the conditional likelihood and
# Stata drops them ("all positive or all negative outcomes"). Categories
# left with no such patients are then dropped, so the reference category is
# the first one that carries information; the categories present before
# that step are kept in the model as levels_with_data, so
# effect_by_level() can report the dropped ones as not estimable.
fit_conditional_logit <- function(data, outcome, terms) {
  model_formula <- as.formula(
    str_glue("{outcome} ~ {terms} + strata(patient_number)")
  )
  complete_rows <- data |>
    drop_na(all_of(all.vars(model_formula))) |>
    droplevels()
  informative_rows <- complete_rows |>
    group_by(patient_number) |>
    filter(n_distinct(.data[[outcome]]) > 1) |>
    ungroup() |>
    droplevels()
  model <- clogit(model_formula, data = informative_rows, method = "exact")
  model$levels_with_data <- list()
  for (variable in all.vars(model_formula)) {
    if (is.factor(complete_rows[[variable]])) {
      model$levels_with_data[[variable]] <- levels(complete_rows[[variable]])
    }
  }
  model
}

Model coefficients

The coefficients and their covariance matrix, from either kind of model the analysis fits: coef() for clogit(), and fixef() for glmer(), whose coef() would give a separate set per patient.

Click to show/hide R Code 
# The estimated coefficients of a clogit() model, or the fixed effects of a
# glmer() model, and their covariance matrix
model_coefficients <- function(model) {
  if (inherits(model, "merMod")) {
    estimates <- fixef(model)
  } else {
    estimates <- coef(model)
  }
  list(estimates = estimates, covariance = as.matrix(vcov(model)))
}

Combine coefficients

The odds ratio, confidence interval and P value for a sum of coefficients, which is what Stata’s lincom …, or reports. The variance of a sum is the sum of every variance and covariance among its terms, which is the sum of every cell of the covariance matrix restricted to those terms; that is the one line of matrix algebra. If a coefficient could not be estimated, it returns missing values rather than an answer from part of the sum.

Click to show/hide R Code 
# Odds ratio, confidence interval and Wald P value for a sum of
# coefficients, as Stata's "lincom ..., or" reports it. Base R matrix algebra
# is needed for the variance of a sum: it is the sum of the variances and
# covariances of the coefficients in the sum.
combine_coefficients <- function(model, terms, level = 0.95) {
  estimates <- model_coefficients(model)$estimates
  if (!all(terms %in% names(estimates)) || anyNA(estimates[terms])) {
    return(tibble(
      log_odds_ratio = NA_real_, std_error = NA_real_,
      odds_ratio = NA_real_, conf_low = NA_real_, conf_high = NA_real_,
      p_value = NA_real_
    ))
  }
  covariance <- model_coefficients(model)$covariance[terms, terms, drop = FALSE]
  log_odds_ratio <- sum(estimates[terms])
  std_error <- sqrt(sum(covariance))
  z <- qnorm(1 - (1 - level) / 2)
  tibble(
    log_odds_ratio = log_odds_ratio,
    std_error = std_error,
    odds_ratio = exp(log_odds_ratio),
    conf_low = exp(log_odds_ratio - z * std_error),
    conf_high = exp(log_odds_ratio + z * std_error),
    p_value = 2 * pnorm(-abs(log_odds_ratio / std_error))
  )
}

Interaction terms

The names R gives interaction coefficients, built from the factor’s levels: for a term post_visit and the factor gender with levels Female and Male, post_visit:genderMale. Building them exactly, rather than matching names that start with post_visit:race, matters here because race and race_group share a prefix.

# The names R gives the coefficients of an interaction between a term and
# each non-reference level of a factor: for example "post_visit:genderMale".
# Built from the levels, so they are found by exact name.
interaction_terms <- function(term, modifier, modifier_levels) {
  str_c(term, ":", modifier, modifier_levels[-1])
}

The visit’s effect within each category

For a model with post_visit and its interaction with a characteristic, the odds ratio for the visit in each category of the characteristic (Methodological background): the post_visit coefficient alone for the reference category, and post_visit plus that category’s interaction coefficient for each other. These are the original code’s lincom commands, done for every category. The synthetic test fits a separate model in each age group and checks that it gives the same odds ratios.

The categories come from the model itself (model$xlevels), so they are exactly those the model used. Categories that had patients but none whose outcome changed were dropped before fitting; they are added back as rows with estimable = FALSE and missing values, so the table always lists every category with data. If a category’s interaction coefficient could not be estimated, its odds ratio is missing; Stata’s lincom would treat the omitted coefficient as zero and report the reference category’s effect under that category’s name.

Click to show/hide R Code 
# The odds ratio for the visit (post_visit) within each level of a
# characteristic, from a model with post_visit and its interaction with that
# characteristic. For the reference level it is the post_visit coefficient;
# for each other level it adds that level's interaction coefficient, as the
# original code's lincom commands did. A category that has patients but
# none whose outcome changed was dropped before fitting
# (fit_conditional_logit()); it is listed with estimable = FALSE and missing
# values, rather than left out silently.
effect_by_level <- function(model, modifier, level = 0.95) {
  modifier_levels <- model$xlevels[[modifier]]
  results <- list()
  for (i in seq_along(modifier_levels)) {
    terms <- "post_visit"
    if (i > 1) {
      terms <- c(terms, str_c("post_visit:", modifier, modifier_levels[i]))
    }
    results[[modifier_levels[i]]] <- combine_coefficients(model, terms, level)
  }
  levels_with_data <- model$levels_with_data[[modifier]]
  if (is.null(levels_with_data)) {
    levels_with_data <- modifier_levels
  }
  bind_rows(results, .id = "level") |>
    mutate(estimable = !is.na(odds_ratio)) |>
    right_join(tibble(level = levels_with_data), by = "level") |>
    mutate(
      estimable = coalesce(estimable, FALSE),
      level = factor(level, levels = levels_with_data)
    ) |>
    arrange(level) |>
    mutate(level = as.character(level))
}

Joint Wald test

The test that a set of coefficients are all zero, b' V⁻¹ b compared with a chi-squared distribution with as many degrees of freedom as coefficients: Stata’s testparm. A coefficient that could not be estimated is left out, as Stata leaves it out. If none can be estimated the test is missing, with zero degrees of freedom; the synthetic test fails if that happens to any interaction test, which would also catch a misspelled coefficient name.

Click to show/hide R Code 
# Joint Wald test that a set of coefficients are all zero, as Stata's
# testparm reports it. Coefficients R could not estimate (NA, as when a
# level has no information) are left out, as Stata omits them; the degrees
# of freedom are the number tested.
wald_test <- function(model, terms) {
  estimates <- model_coefficients(model)$estimates
  terms <- terms[terms %in% names(estimates) & !is.na(estimates[terms])]
  if (length(terms) == 0) {
    return(tibble(chi_squared = NA_real_, df = 0L, p_value = NA_real_))
  }
  # Base R matrix algebra: the Wald statistic b' V^-1 b
  b <- estimates[terms]
  covariance <- model_coefficients(model)$covariance[terms, terms, drop = FALSE]
  chi_squared <- as.numeric(t(b) %*% solve(covariance) %*% b)
  tibble(
    chi_squared = chi_squared,
    df = length(terms),
    p_value = pchisq(chi_squared, df = length(terms), lower.tail = FALSE)
  )
}

Odds ratio table

Every coefficient of a model as an odds ratio with its confidence interval and P value, the table Stata prints with the or option. It uses combine_coefficients() with one term at a time, so its intervals and P values are computed exactly as the within-category ones are.

Click to show/hide R Code 
# Every coefficient as an odds ratio with a Wald confidence interval and P
# value, as Stata's "or" option shows them. Works for clogit() and glmer()
# models; for glmer() these are the fixed effects.
tidy_odds_ratios <- function(model, level = 0.95) {
  estimates <- model_coefficients(model)$estimates
  results <- list()
  for (term in names(estimates)) {
    results[[term]] <- combine_coefficients(model, term, level)
  }
  bind_rows(results, .id = "term")
}

Pair an outcome

One row per patient with the outcome’s value before and after the visit, made from the long data with pivot_wider(), plus the patient’s characteristics: the layout paired_mcnemar() needs when it is run within each category for Tables 2 to 4.

Click to show/hide R Code 
# One row per patient with an outcome's value before (before) and after
# (after) the visit, and the patient's characteristics, from the long data:
# the layout paired_mcnemar() needs for a subgroup. The characteristics are
# the same in both of a patient's rows.
pair_outcome <- function(cohort_long, outcome, characteristics) {
  cohort_long |>
    select(patient_number, all_of(characteristics), post_visit, all_of(outcome)) |>
    pivot_wider(
      names_from = post_visit,
      values_from = all_of(outcome),
      names_prefix = "period_"
    ) |>
    rename(before = period_0, after = period_1)
}

Count categories

For Table 1: each category’s number of patients and column percentage, with printed labels. A cohort that lacks the characteristic altogether gives no rows, so its cells stay empty rather than appearing as a column of unknowns.

Click to show/hide R Code 
# For Table 1: the number and column percentage of patients in each
# category of one characteristic, labelled as the article prints them.
# A characteristic the cohort does not have gives no rows, so its cells
# stay empty rather than being counted as unknown.
count_categories <- function(patients, characteristic, printed_labels) {
  if (!characteristic %in% names(patients)) {
    return(tibble(row_label = character(), n = integer(), pct = character()))
  }
  patients |>
    count(level = .data[[characteristic]]) |>
    filter(!is.na(level)) |>
    mutate(
      row_label = relabel_levels(as.character(level), printed_labels),
      pct = style_percent(n / nrow(patients), suffix = "%")
    ) |>
    select(row_label, n, pct)
}

Format a row of Tables 2 to 4

Turns one paired_mcnemar() result into the text cells of a row. gtsummary’s style_percent(), style_ratio() and style_pvalue() do the rounding. An odds ratio with no worsened pairs is infinite and printed “∞”, as the article’s Table 4 prints it; with no discordant pairs there is no odds ratio and the cell is empty.

Click to show/hide R Code 
# For Tables 2 to 4: one row of text from a paired_mcnemar() result, the
# columns format_outcome_table() expects. An odds ratio with no worsened
# pairs is infinite and printed as the article prints it; with no
# discordant pairs at all there is none, and the cell is empty.
format_change <- function(result) {
  odds_ratio_text <- str_glue(
    "{style_ratio(result$odds_ratio)} ",
    "({style_ratio(result$conf_low)}–{style_ratio(result$conf_high)})"
  )
  tibble(
    n = as.character(result$n_pairs),
    before_n = as.character(result$n_before),
    before_pct = style_percent(result$n_before / result$n_pairs, suffix = "%"),
    after_n = as.character(result$n_after),
    after_pct = style_percent(result$n_after / result$n_pairs, suffix = "%"),
    odds_ratio = case_when(
      is.na(result$odds_ratio) ~ "",
      is.infinite(result$odds_ratio) ~ "∞",
      .default = as.character(odds_ratio_text)
    ),
    p_value = coalesce(style_pvalue(result$p_value, digits = 3), "")
  )
}

Add group headings

Inserts a heading row (Sex, Race and so on) before each characteristic’s categories, as the article’s tables have, and moves the test across groups onto that heading row, so it sits with the characteristic it tests. The Total row is not given a heading.

Click to show/hide R Code 
# Insert a heading row before each group's categories (Sex, Race, ...), and
# rename row_label to label, the column gtsummary shows first. Columns named
# in move_to_heading (the test across groups) move from the group's first
# row to its heading. The Total row is a group of one and gets no heading.
add_group_headings <- function(rows, move_to_heading = character()) {
  rows <- rows |>
    mutate(group = factor(group, levels = unique(group)), row_type = "level")
  headings <- rows |>
    group_by(group) |>
    slice(1) |>
    ungroup() |>
    filter(group != "Total") |>
    mutate(
      row_label = as.character(group),
      row_type = "heading",
      across(-c(group, row_label, row_type, all_of(move_to_heading)), \(x) "")
    )
  rows <- rows |>
    mutate(across(all_of(move_to_heading), \(x) if_else(group == "Total", x, "")))
  bind_rows(headings, rows) |>
    mutate(heading_first = row_type != "heading") |>
    arrange(group, heading_first) |>
    select(-heading_first) |>
    mutate(group = as.character(group), across(everything(), \(x) coalesce(x, ""))) |>
    rename(label = row_label) |>
    relocate(label)
}

## Conditional logistic regression

The model behind most results ([Methodological background](methodological_background.qmd#conditional-logistic-regression)). `strata(patient_number)` makes each patient a stratum, the R version of Stata's `group(PatientNumber)`, and `method = "exact"` asks for the exact conditional likelihood, which is what Stata's `clogit` computes. The terms are passed as text so the scripts can build many models in loops.

In the RUSH-era models the terms leave out the main effect of a characteristic that is the same in a patient's two records. Stata drops such a term automatically, with a note; R's `clogit()` would return its coefficient as `NA`. Leaving it out gives the same model and the same coefficients. The era models keep it, because there a characteristic can change between a patient's two visits ([5. Comparison with the pre-RUSH era](05_compare_eras.qmd#does-the-pattern-differ-by-characteristic)).

The estimation sample is built as Stata's `clogit` builds it: rows that have every variable the model uses, then only patients whose outcome differs between their rows. A patient with the same outcome in every row, or with one row (a viral load in one window only), adds nothing to the conditional likelihood; Stata drops them with a note about "all positive or all negative outcomes". Categories left with no such patients are then dropped too, so the reference category is the first one that carries information. Without that step, if the first category had only uninformative patients, `clogit()` would silently drop another category's interaction instead and the effects would be labelled with the wrong categories. The categories that had patients before the step are kept with the model, so the next functions can report the dropped ones as not estimable rather than leave them out.
