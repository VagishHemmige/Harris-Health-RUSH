Differences from the original code

Author

Vagish Hemmige

PendingProvisional

Text highlighted like this is provisional: it depends on a decision the analysis plan has not yet made.

The original analysis is the Stata file of 15 January 2015, shown on Original Stata code. This page lists every way the R version differs from it. Most are translations: the same step written the way R does it. A few change what is computed; each is marked, and none changes a published estimate unless the data are as described. Whether a difference changes a number can only be confirmed by running both versions on the study data, which has not yet been done.

What is the same

The R version reads the same workbooks and sheets, numbers the categories the same way, uses the same reference categories, fits the same conditional logistic regressions to the same records with the same exact conditional likelihood, tests the same interaction terms, skips the same models the original could not fit, and restricts the era comparison by the same rule. Methodological background has a table of the Stata commands and their R equivalents.

Differences in what is reported

  • Within-category odds ratios and interaction tests for every characteristic. The original code ran testparm and lincom for most characteristics, but for sex only lincom (with one interaction term, that term’s own P value is the test), and for race as recorded neither. The R version computes both for every characteristic. This only adds output.
  • Multivariable models are tabulated as odds ratios for every coefficient, as Stata’s or option showed them.
  • Printed checks. R’s quantile() and Stata’s summarize, detail define percentiles slightly differently; R’s count() shows a row for missing values where Stata’s tab without missing hides it. paired_mcnemar() does not print the matched-pairs odds ratio that mcc prints (the conditional logistic regression gives it), and the random-intercept tables do not show xtlogit’s intercept variance or its test that the variance is zero. None of these affects an estimate.
  • Unused variables are not made. The original code created HIV_tested_During_Visit (always 1) and encoded IndexTest_Place before dropping it; neither was used in any analysis.

Differences that could change a number

  • Sex and age group in the stacked eras. The original code encoded each sheet separately and then appended them, so the stacked data carried the study sheet’s numeric codes for sex and age group, with its labels. If the two sheets had the same set of recorded values, the codes agree and the results are the same. If a value was absent from one sheet, the codes after it would shift and a category would be mislabelled. The R version stacks the recorded text instead, so this cannot happen. Whether the sheets’ value sets match is part of the first run on the study data.
  • An omitted coefficient in a within-category odds ratio. If an interaction coefficient cannot be estimated, effect_by_level() reports that category’s odds ratio as missing. Stata’s lincom treats an omitted coefficient as zero and reports the reference category’s odds ratio for it. R’s answer is the honest one; it changes only categories for which Stata’s number was not an estimate.
  • Patients with no informative pairs. Like Stata, the R version fits each model to the patients whose outcome changed, and picks the reference category among the categories that still have such patients. A category with none is listed as not estimable. Stata drops the same patients; how its lincom output labels a category left with none has not been checked. Without this step the R version could have labelled one category’s odds ratio with another’s name.
  • Repeated patient numbers stop the import, as Stata’s merge 1:1 and reshape would have; the R join and reshape alone would not have.
  • McNemar’s test with no discordant pairs returns missing statistics instead of an error, so the other outcomes still run.
  • Excel column types. read_excel() is told to guess each column’s type from every row, as Stata’s import excel types the whole column. With R’s default of 1,000 rows, a viral load column empty in its first rows could have lost its later values.
  • Random-intercept models. Stata’s xtlogit and R’s glmer() both integrate over the random intercept by adaptive Gauss–Hermite quadrature with 12 points, but with different optimizers. Their estimates should agree closely, not exactly.

Kept as in the original, and still to check

These are not changed, because changing them would depart from the published analysis; each is recorded so it can be checked.

  • Race groups from numeric codes. The original code built the four race groups, and the African American indicator, from encode’s numeric codes, with a different list of codes for each sheet, because each sheet’s values were numbered separately. The R version does the same, with the code lists in R/setup.R, and prints the table of code, recorded value and group so it can be checked (issue #4).
  • The African American indicator when race is missing. Stata’s generate AfricanAmerican=(Race==2) is 0 for a patient with no recorded race, so those patients count as not African American in the African American models and the first set of multivariable models, while the race-group and race models leave them out. The R version reproduces this. It means the two multivariable versions can rest on slightly different samples.
  • Unmatched patients in the merge. The original code merged the years-since-diagnosis workbook one to one and kept every row, printing how many matched. A patient in only one file stays in the data with the other file’s columns missing. The R version does the same and prints the same counts.

The era-comparison sample

The original code fitted the era comparison twice, with every patient and with only the patients who had a visit in both eras. The R version fits both.

Decision pending: which of the two samples produced the P values the article reports (decision issue #2).

McNemar’s test for viral suppression

The original code ran McNemar’s test for engagement and retention only. The R version does the same.

Decision pending: whether to add it for viral suppression, as the article’s Methods describe (decision issue #3).

Added: the article’s tables

The Stata code makes none of the article’s four tables. R/tables.R builds them with gtsummary, in the article’s layout, so the code shows how each was made:

  • Table 1 counts each cohort’s patients by sex, race group, visit year (paired by position across eras), age group and years since diagnosis. The control sheet holds no years since diagnosis; the controls are the same patients, so their groups are taken from the years workbook by patient number. That workbook gives years to the RUSH-era index visit, so the controls’ column uses that value. The Stata code never uses years since diagnosis for the controls; the article’s control column, which may be years to the pre-RUSH visit, probably came from the SPSS work the article mentions, so the two columns need not match.
  • Tables 2 to 4 show, for each subgroup, the patients with both values, the number with the outcome before and after, McNemar’s matched-pairs odds ratio with the exact interval Stata’s mcc reports, its chi-squared P value, and, once per characteristic, the interaction test of 4. RUSH-era models. The article’s χ² values fit tests with one fewer degree of freedom than categories, as the interaction test has. Whether these are exactly the statistics behind the published columns (the exact or the chi-squared McNemar P value, for instance) is part of #5.

The site shows the four tables with the article’s own printed values, run through the same formatting functions (Published results).

Not ported

  • Mean age, in the article’s Results, was not computed by the Stata code, and the workbooks hold age groups only; the article says SPSS 21 was also used (Flash et al. 2015).
  • Building the cohort and the outcomes from the laboratory, medical record and Ryan White data happened before the Stata analysis and is not in either version.

References

## Differences in what is reported

- **Within-category odds ratios and interaction tests for every characteristic.** The original code ran `testparm` and `lincom` for most characteristics, but for sex only `lincom` (with one interaction term, that term's own P value is the test), and for race as recorded neither. The R version computes both for every characteristic. This only adds output.
- **Multivariable models** are tabulated as odds ratios for every coefficient, as Stata's `or` option showed them.
- **Printed checks.** R's `quantile()` and Stata's `summarize, detail` define percentiles slightly differently; R's `count()` shows a row for missing values where Stata's `tab` without `missing` hides it. `paired_mcnemar()` does not print the matched-pairs odds ratio that `mcc` prints (the conditional logistic regression gives it), and the random-intercept tables do not show `xtlogit`'s intercept variance or its test that the variance is zero. None of these affects an estimate.
- **Unused variables are not made.** The original code created `HIV_tested_During_Visit` (always 1) and encoded `IndexTest_Place` before dropping it; neither was used in any analysis.

## Differences that could change a number

- **Sex and age group in the stacked eras.** The original code encoded each sheet separately and then appended them, so the stacked data carried the study sheet's numeric codes for sex and age group, with its labels. If the two sheets had the same set of recorded values, the codes agree and the results are the same. If a value was absent from one sheet, the codes after it would shift and a category would be mislabelled. The R version stacks the recorded text instead, so this cannot happen. Whether the sheets' value sets match is part of the first run on the study data.
- **An omitted coefficient in a within-category odds ratio.** If an interaction coefficient cannot be estimated, `effect_by_level()` reports that category's odds ratio as missing. Stata's `lincom` treats an omitted coefficient as zero and reports the reference category's odds ratio for it. R's answer is the honest one; it changes only categories for which Stata's number was not an estimate.
- **Patients with no informative pairs.** Like Stata, the R version fits each model to the patients whose outcome changed, and picks the reference category among the categories that still have such patients. A category with none is listed as not estimable. Stata drops the same patients; how its `lincom` output labels a category left with none has not been checked. Without this step the R version could have labelled one category's odds ratio with another's name.
- **Repeated patient numbers** stop the import, as Stata's `merge 1:1` and `reshape` would have; the R join and reshape alone would not have.
- **McNemar's test with no discordant pairs** returns missing statistics instead of an error, so the other outcomes still run.
- **Excel column types.** `read_excel()` is told to guess each column's type from every row, as Stata's `import excel` types the whole column. With R's default of 1,000 rows, a viral load column empty in its first rows could have lost its later values.
- **Random-intercept models.** Stata's `xtlogit` and R's `glmer()` both integrate over the random intercept by adaptive Gauss–Hermite quadrature with 12 points, but with different optimizers. Their estimates should agree closely, not exactly.
